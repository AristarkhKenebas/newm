# newm как экран входа (greetd)

[English](../en/greeter.md) · **Русский**

newm может сам быть экраном входа. [greetd](https://sr.ht/~kennylevinsen/greetd/) — маленькая
служба входа в систему: она запускает программу-*приветствие* (greeter) и даёт ей впускать
пользователей. newm умеет быть таким приветствием. Тогда сразу после включения компьютера вы
видите экран блокировки newm: выбираете пользователя, вводите пароль — и начинается ваш сеанс
newm. Не нужна вторая программа, и вид не меняется между экраном входа и рабочим столом.

Как это происходит:

1. greetd запускает `newm` от своего пользователя-приветствия (обычно `greeter`; в Void —
   `_greeter`).
2. newm понимает, что он приветствие, и показывает свой экран блокировки: сначала спрашивает
   пользователя (список тех, кто может войти), потом пароль.
3. greetd проверяет пароль своей службой PAM (файлы паролей системы newm не видит).
4. newm просит greetd запустить ваш сеанс и завершается. greetd запускает этот сеанс от
   вашего имени: по умолчанию снова newm (иначе — то, что указано в `greeterCommand`).

## Что нужно

- **greetd** 0.8 или новее из вашего дистрибутива (`greetd`; в Gentoo — `gui-libs/greetd`).
- **newm, установленный для всех**: `./install.sh` (без `--user`: `/usr/local/bin/newm`),
  пакет дистрибутива или модуль NixOS. Пользователь-приветствие не может запустить newm из
  вашей домашней папки.
- **Java 27**, которую этот пользователь найдёт: системная (`/usr/lib/jvm/...`) или
  `JAVA_HOME`; стартовый скрипт newm сам ищет в `/usr/lib/jvm`.
- **Место (seat)**: greetd открывает для приветствия сеанс входа, поэтому с systemd-logind или
  elogind ничего делать не нужно. С **seatd** добавьте пользователя-приветствие в группу seatd
  (`sudo usermod -aG _seatd _greeter` в Void, `seat` в большинстве остальных) — так же, как
  вы добавляли себя.

## Настройка

`/etc/greetd/config.toml` (раздел `[terminal]` и строку `user`, которые записал пакет,
оставьте; меняется только команда):

```toml
[terminal]
vt = 1

[default_session]
command = "/usr/local/bin/newm"   # или /usr/bin/newm из пакета
user = "greeter"                  # Void: "_greeter", Debian: "_greetd"
```

Затем включите greetd вместо прежнего экрана входа:

```sh
sudo systemctl disable sddm gdm ly 2>/dev/null; sudo systemctl enable greetd   # systemd
sudo ln -s /etc/sv/greetd /var/service/                                        # Void (runit)
sudo rc-update add greetd default                                              # Alpine (greetd-openrc)
```

Ключа `--greeter` нет: newm узнаёт, что он приветствие, потому что greetd передаёт ему свой
сокет (`GREETD_SOCK`), или потому что он запущен от пользователя из настройки `greeterUser`.

## Пользователь-приветствие и его настройки

Пользователь-приветствие — системный пользователь без пароля и без собственных прав; его
создаёт greetd (`greeter`, `_greeter`, `_greetd`). newm от его имени может только показывать
экран входа и говорить с greetd; ваши файлы он прочитать не может.

Его конфигурация ищется как у всех: собственный `~/.config/newm/config.kts` приветствия, если
в его домашнюю папку можно писать (newm в первый раз запишет его из `/etc/newm`), иначе
напрямую **`/etc/newm/config.kts`** (или `config.lua`, `config.json`). Поэтому вид экрана входа
проще всего задавать в `/etc/newm/config.kts` — его пишет `newm install-session`, и с него
начинают новые пользователи. Журнал: `~/.local/state/newm/newm.log` приветствия, если туда
можно писать, иначе журнал самого greetd (`journalctl -u greetd` или консоль, на которой
работает greetd).

## Настройки

| Настройка | По умолчанию | Что значит |
|---|---|---|
| `greeterUser` | `"greeter"` | пользователь, от которого greetd запускает приветствие. Нужна, только если greetd не передал newm свой сокет; с greetd newm узнаёт это сам. |
| `greeterCommand` | этот newm | что greetd запускает, когда пользователь впущен: `"newm"`, `"/usr/local/bin/newm"`, свой скрипт. Слова делятся по пробелам (без кавычек). |
| `lock { }` | экран блокировки newm | вид и размер экрана входа — это вид экрана блокировки: `w`, `h`, `cornerRadius`, `clock`, `showOnLock`, `program`/`cmd` ([Все настройки](settings.md#lock--launcher-)). |
| `startupSound { enabled }` | `false` на экране входа | звук запуска (иначе он прозвучал бы дважды: приветствие, потом ваш сеанс). |

В `config.kts`:

```kotlin
greeterCommand = "/usr/local/bin/newm"
lock {
    clock = "HH:mm"
}
```

В `config.json` (`programs.newm.settings` в NixOS): `"greeter_command"`, `"greeter_user"`.

## Как запускается ваш сеанс

Когда пароль верный, newm отправляет greetd `start_session` с `greeterCommand` (если не задано —
тот же newm, что работает как приветствие, полным путём) и завершается; greetd закрывает сеанс
приветствия и запускает ваш этой командой, от вашего имени, с вашим окружением. Дальше newm
запускается как обычно, с вашей конфигурацией.

В системе без systemd (Void, Gentoo с OpenRC, Alpine) сеансовую шину D-Bus при входе никто не
запускает; стартовый скрипт newm замечает это и сам запускает newm внутри `dbus-run-session`
(см. [Установку](install.md#запуск)). Добавлять для этого что-то в `greeterCommand` не нужно.

Если greetd не принял команду (такой программы нет), в журнале приветствия будет
`greetd did not take the session`, и greetd снова покажет экран входа.

## NixOS

Модуль newm настраивает greetd сам:

```nix
programs.newm = {
  enable = true;
  greeter.enable = true;   # greetd с newm в роли приветствия (пользователь "greeter")
  # Вид экрана входа и конфигурация новых пользователей (/etc/newm/config.json):
  settings = { panels.lock.corner_radius = 30; };
};
```

Он включает `services.greetd` и задаёт `default_session.command` = newm (по умолчанию: ваш
собственный `services.greetd.settings.default_session.command` важнее). Другой экран входа
выключите (`services.displayManager.sddm.enable = false`, ...).

## Если что-то не так

- **Текстовая консоль, или greetd раз за разом запускает приветствие заново**: newm не смог
  запуститься как приветствие. Войдите на другой консоли (Ctrl+Alt+F2) и посмотрите журнал
  greetd: `journalctl -u greetd -b` с systemd, иначе — консоль, на которой работает greetd.
  Частые причины: у этого пользователя нет Java, newm установлен с `--user`, нет прав на место
  (группа seatd).
- **В журнале `Not in a greetd session`**: newm запущен от `greeterUser`, но не через greetd
  (нет `GREETD_SOCK`). Запускайте его через greetd или задайте в `greeterUser` другого
  пользователя, не вашего.
- **Вашего пользователя нет в списке**: список — это `getent passwd` без приветствия и без
  пользователей, у которых оболочка `nologin` или `false`.
- **Пароль верный, но ничего не запускается**: причина в журнале приветствия
  (`greetd did not take the session ...`): проверьте `greeterCommand` и что такая команда есть
  у вашего пользователя.
- **Без systemd после входа нет трея и уведомлений**: установите D-Bus (`dbus-run-session`),
  см. [Установку](install.md#запуск).
- **Экран входа долго появляется**: AOT-кэш Java лежит в `~/.cache/newm/aot` приветствия; если в
  его домашнюю папку писать нельзя, кэша нет и каждый запуск холодный. Если дать
  пользователю-приветствию домашнюю папку с правом записи (пакеты greetd часто используют
  `/var/lib/greetd`), следующие запуски будут быстрее.
