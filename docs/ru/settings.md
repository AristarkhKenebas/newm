# Все настройки

[English](../en/settings.md) · **Русский**

`config.kts`, который пишет newm, перечисляет основные настройки с пояснением к каждой. Эта
страница — полный справочник. Настройка, которую вы не указали, имеет значение по умолчанию,
указанное здесь; стартовый `config.kts` задаёт некоторые из них иначе (он у вас перед глазами,
смотрите там).

В Lua и JSON имена те же, в snake_case (`cornerRadius` → `corner_radius`, `topBar` →
`top_bar`; одно исключение: `numLock` — это `numlock`). `newm cmd config` выводит все
действующие настройки.

## Верхний уровень

| Настройка | По умолчанию | Что |
|---|---|---|
| `animTime` | `0.3` | сколько длятся перемещение и масштабирование, секунды (общее время анимаций; они идут, только когда включены) |
| `blendTime` | `1.0` | плавное появление при запуске и исчезновение при выходе, секунды (анимации `startup`, `quit`) |
| `animations { }` | выключены | все анимации, как в Hyprland: `preset = "newm"` (привычный вид newm), `enabled`, `millis`, `curve`, `curve(имя, …)`, `spring(имя, …)`, `animation(имя, enabled, millis, curve, style, speed)`, `on(имя)`, `off(имя)` — см. [Анимации](animations.md) |
| `cornerRadius` | `18` | скругление углов самого экрана, пиксели (0: прямые) |
| `lockOnWakeup` | `true` | блокировать экран перед сном (сон ждёт экран блокировки, см. `lock { sleepWait }`) и когда компьютер просыпается |
| `colorScheme` | `"auto"` | `"dark"`, `"light"` или `"auto"`: последний выбор в быстрых настройках (пока нет — тёмная) |
| `language` | `"auto"` | язык меню newm: `"auto"` (язык системы), `"en"`, `"ru"` |
| `enableUnlockCommand` | `false` | `newm cmd unlock` снимает блокировку без пароля: только на компьютере для тестов |
| `greeterUser` | `"greeter"` | пользователь, от которого greetd запускает экран входа (см. [newm как экран входа](greeter.md)); запущенный через greetd, newm узнаёт, что он экран входа, по сокету greetd, как бы ни звали пользователя |
| `greeterCommand` | этот newm | что greetd запускает, когда экран входа впустил пользователя; слова разделяются по пробелам (кавычек нет: для пути с пробелами нужен свой скрипт) |
| `timeFormat` | `"HH:mm"` | как пишется время суток (java.time: `"h:mm a"`): история уведомлений, экран блокировки, буфер обмена |
| `terminal` | `$TERMINAL`, иначе первый установленный (alacritty, foot, kitty, ...) | терминал, который открывает newm: действие `"terminal"`, `defaultTerminal()`, программы, работающие в терминале (Terminal=true); `"foot"`, `"kitty -1"` |

## warmup { }

Работа старта, сделанная заранее, и память, отданная после неё. (Выключать их стоит только
чтобы увидеть, что они меняют: каждая чуть стоит на старте и избавляет от рывка потом.)

| Настройка | По умолчанию | Что |
|---|---|---|
| `enabled` | `true` | меню newm один раз рисуются заранее, вне экрана, вскоре после старта: первое открытие быстрое |
| `restMillis` | `800` | каждое меню рисуется заранее только когда указатель стоит столько (мс): остальная работа старта идёт первой |
| `ownThread` | `true` | меню (и панели, до показа newm) рисуются заранее в отдельном потоке и не занимают композитор (то, что меню делает при открытии — поиск Wi-Fi, Bluetooth, звук, команды, — при этом не происходит); `false`: в потоке композитора, по одному за кадр, как раньше (каждое задерживает указатель на ~0,1–0,3 с) |
| `compose` | `true` | Compose (панель, меню) готовится в отдельном потоке, пока newm стартует (иначе первый кадр панели занимает композитор ~0,7 с) |
| `collect` | `true` | после рисования заранее куча Java снова становится маленькой: одна полная сборка (10–50 мс, пока указатель стоит) |

## windows { }

Где открываются новые окна и дочерние окна программы (см. [Каждый день](using.md#где-открываются-окна)).

| Настройка | По умолчанию | Что |
|---|---|---|
| `newPlacement` | `"compact"` | новое окно: `"compact"` (свободное место рядом с вашим, при котором окна остаются плотно и ближе к квадрату, а вид сдвигается меньше всего; ничего не сдвигается, если рядом с вашим есть свободное место, а если нет — сдвигается как можно меньше окон; на экранах: ваш экран, иначе соседний со свободным местом, иначе новый экран сразу после вашего), `"right-of-focused"` (справа от вашего, окна правее сдвигаются), `"beside-focused"` (первая свободная плитка справа от вашего, ничего не двигается), `"end"` (правее всех окон), `"original"` (как в newm: первая свободная плитка в виде, по рядам) |
| `childPlacement` | `"below"` | дочернее окно (диалог, просмотр фото): `"below"` — под родителем (на свободное место там, иначе что ниже, сдвигается вниз), `"right"` — справа от него (так же), `"over"` — плавает поверх (как в newm) |
| `returnFocusToParent` | `true` | при закрытии дочернего окна фокус возвращается родителю (или окну, бывшему в фокусе, когда оно открылось); `false`: ближайшему окну, как в newm |
| `childBySameApp` | `true` | окно без родителя, открытое программой окна в фокусе (то же соединение и app id, как просмотр фото Telegram), считается его дочерним |
| `childBySameAppExcept` | терминалы, браузеры | app id, чьи новые окна так дочерними не считаются (`["foot", "kitty", "firefox", ...]`) |

## screens { }

Стена из целых экранов: экран — ровно место монитора, оставленное панелями; на нём до
`windowsPerScreen` окон, разложенных его раскладкой, а следующее окно открывается на
следующем экране. Переход между окнами одного экрана не двигает вид; к окну другого экрана
вид сдвигается ровно на один экран. Свайпы встают на целые экраны; отдаление и обзор
показывают экраны рядом.

| Настройка | По умолчанию | Что |
|---|---|---|
| `enabled` | `true` | экраны; `false` — свободная стена плиток newm (как в оригинале) |
| `windowsPerScreen` | `2` | сколько окон делят экран (4 — половины и четверти, как в Hyprland) |
| `layout` | `"columns"` | `"columns"` (рядом), `"rows"`, `"grid"` (половины, потом четверти), `"dwindle"`, `"spiral"`, `"master"` (одно большое окно и полосы, как в i3/xmonad), `"centered-master"`, `"monocle"` (одно окно на экран, как в оригинале) или одна из `customLayout(...)` |
| `masterRatio` | `0.6` | доля главного окна (`"master"`, `"centered-master"`) |
| `masterSide` | `"left"` | `"left"`, `"right"`, `"top"`, `"bottom"` |
| `gaps` | `0` | больше места между окнами и вокруг них, в пикселях (`view { padding }` есть и так) |
| `overflow` | `"right"` | где следующий экран: `"right"` или `"down"` |
| `pullBack` | `true` | окно закрылось — оставленный промежуток закрывается, как говорит `pullBackMode`; `false` — экраны остаются как есть |
| `pullBackMode` | `"compact"` | `"compact"`: соседний экран, все окна которого помещаются на освободившееся место, переезжает туда (экраном меньше), больше ничего не двигается; `"shift"`: окна всех следующих экранов подтягиваются на одно место, пока его экран снова не заполнится |
| `windowsUnderBar` | `false` | `true` — окна продолжаются под панелями (стена newm: верхнее окно было видно сквозь панель) |
| `cycle` | columns, rows, grid, master, monocle | раскладки, которые перебирает `next-layout` (Super+Space) |
| `customLayout(name, layout)` | — | своя раскладка: любой `dev.caulis.tiling.Layout` (`MasterStack(ratio = 0.7)`, свой) |

Новое окно встаёт на экран в фокусе, сразу после окна в фокусе; если экран полон — на соседний
экран со свободным местом (следующий, затем предыдущий), иначе на новый экран сразу после него
(`windows { newPlacement }`: `"right-of-focused"` — всегда новый экран, `"end"` — последний
экран, `"original"` — первый со свободным местом). Дочернее окно встаёт сразу после своего окна;
если экран полон — на следующий экран, если там есть место, иначе на новый. У каждого экрана
может быть своя раскладка, пока newm работает (Super+Space).

## resize { }

Размер окон на экранах: окно растёт только в пределах своего экрана, соседи по экрану
уступают место; чтобы места было больше, сначала отдалите вид (окно всё равно остаётся в
пределах экрана). В обзоре размер не меняется. Экран хранит размеры, пока не изменятся его
окна или раскладка.

| Настройка | По умолчанию | Что |
|---|---|---|
| `quarters` | `true` | четверть, за которую взяли (Super + правая кнопка), выбирает угол, как в Hyprland; `false` — всегда правый нижний |
| `onBorder` | `true` | промежуток рядом с окном, если тянуть его без Super, меняет размер окна |
| `borderGrabSize` | `10` | насколько далеко от окна можно взять его край, в пикселях |
| `borderButton` | `"left"` | кнопка, которой тянут край |
| `mouseButton` | не задано | кнопка размера с зажатой Super (не задано: `mouse { resizeButton }`) |
| `clampToScreen` | `true` | ничто не вырастает за края своего экрана |
| `keepAspect` | `false` | угол сохраняет форму окна |
| `minSize` | `0.1` | самое маленькое окно, доля экрана |
| `keyStep` | `0.1` | на сколько Super+Ctrl+стрелки двигают край, доля экрана |

## focus { }

| Настройка | По умолчанию | Что |
|---|---|---|
| `enabled` | `true` | линия вокруг окна в фокусе |
| `color` | `"auto"` | `"auto"` (акцент цветов), `"#RRGGBB"` или `"#RRGGBBAA"` |
| `distance` | `4.0` | на каком расстоянии от окна, пиксели |
| `width` | `2.0` | толщина, пиксели |
| `animTime` | `0.3` | сколько длится её собственный переезд (анимация `border`) |
| `animateOnChange` | `false` | линия переезжает к следующему окну |
| `urgentColor` | `""` | рамка окна, которое просит внимания, пока оно не в фокусе (фокус снимает эту просьбу), как в Hyprland; `""`: без неё |
| `shader` | `""` | свой GLSL-файл, `vec4 paint(vec2 at)`, перечитывается при сохранении (см. ниже) |
| `animate` | `true` | `false`: собственное время шейдера (и вращение градиента) стоит |

`color` и `urgentColor` понимают и запись цветов рамки из Hyprland: градиент
`"rgba(33ccffee) rgba(00ff99ee) 45deg"`, `"rgb(ff5555)"`, `"0xffaabbcc"`.

Шейдер рамки получает всё, что Caulis даёт любому шейдеру рамки: `at` (0..1 в прямоугольнике),
`time`, `size`, `pixel`, `progress` (0..1 вдоль рамки, по часовой стрелке от левого верхнего
угла), `borderWidth`, `cornerRadius`, `focused`, `urgent`, `colors[0]` (= `color`), `colors[1]`
(= `urgentColor`). Ошибка в нём показывается уведомлением с номером строки, а рамка пока
рисуется цветом `color`. Три примера для начала:

```glsl
// Радуга, бегущая вокруг окна
vec4 paint(vec2 at) {
    float hue = fract(progress + time * 0.2);
    return vec4(clamp(abs(mod(hue * 6.0 + vec3(0.0, 4.0, 2.0), 6.0) - 3.0) - 1.0, 0.0, 1.0), 1.0);
}
```

```glsl
// Пульсирующее свечение заданного цвета (красное, если окно просит внимания)
vec4 paint(vec2 at) {
    vec3 base = urgent > 0.5 ? vec3(1.0, 0.3, 0.3) : colors[0].rgb;
    return vec4(base * (0.55 + 0.45 * sin(time * 3.0)), 1.0);
}
```

```glsl
// Бегущие муравьи
vec4 paint(vec2 at) {
    float dash = step(0.5, fract((progress * 2.0 * (size.x + size.y) - time * 40.0) / 16.0));
    return mix(vec4(0.1, 0.1, 0.1, 1.0), vec4(1.0, 0.85, 0.2, 1.0), dash);
}
```

## specialWorkspace { }

Особые рабочие столы из Hyprland (special): слой окон над стеной, на мониторе с фокусом, на
месте самого экрана (камера стены его не двигает), со своей маленькой раскладкой; всё за ним
затемнено (и размыто). Клавиши: `toggleSpecialWorkspace("name")` (`"special"` — без имени),
`moveToSpecialWorkspace("name", silent = false)`, `moveOutOfSpecialWorkspace()`; в config.json/Lua
действия `special-workspace toggle [name]`, `move-to-special [name] [silent]`,
`move-out-of-special`, `move-to-workspace special:name`; из терминала `newm cmd special [name]`.
Окно, перенесённое туда, уходит со стены; вынесенное обратно — возвращается на стену как новое
(встаёт, как новое окно: рядом с окном, бывшим в фокусе) и получает фокус. `from-special-workspace`
выносит окно в фокусе, а если особый стол спрятан — окно, бывшее в нём в фокусе последним.
Super+перетаскивание окна показанного особого стола на затемнённую стену вокруг тоже выносит
его (отпущенное внутри, оно возвращается на своё место). Обзор показывает только стену:
показанный особый стол прячется, когда обзор открывается, а показ особого стола из обзора
(Super+M) закрывает обзор. Блокировка тоже его прячет.

Его окна выглядят как окна стены: скруглённые углы (`view { cornerRadius }`), отступ вокруг
каждого (`view { padding }`: между двумя окнами — вдвое больше), рамка фокуса из `focus { }`,
размытие и прозрачность из `view { rules }`. Окна раскладываются как у Hyprland (dwindle) внутри
`gap`, по центру, размером `size` — это отдельный экран, не часть экранов стены. Пока он показан
(и `clickOutsideHides`), указатель над затемнённой стеной не забирает у него фокус.

| Настройка | По умолчанию | Что |
|---|---|---|
| `dim` | `0.4` | насколько темнее стена за ним |
| `blurRadius` | `0` | насколько размыта стена за ним (0: не размыта) |
| `blurPasses` | `2` | насколько гладкое размытие |
| `gap` | `40` | отступ от краёв экрана, пиксели |
| `size` | `1.0` | какую часть экрана он занимает (0.2–1) |
| `animation` | `"scratchpads"` | анимация появления и ухода его окон (выключена, пока анимации не включены) |
| `hideWhenEmpty` | `true` | прячется, когда закрылось или ушло последнее окно |
| `newWindowsJoin` | `true` | окна, открытые, пока он показан, попадают в него |
| `clickOutsideHides` | `true` | щелчок по затемнённой стене прячет его |
| `hideInOverview` | `true` | обзор прячет его |
| `cornerRadius` | `-1` | скругление углов его окон, пиксели (-1: как `view { cornerRadius }`) |
| `padding` | `-1` | отступ вокруг каждого его окна, пиксели (-1: как `view { padding }`) |

### Программа, которая всегда открывается там: Spotify в «music»

Правило отправляет программу на особый стол, когда она открывается: на стене она не
появляется, ждёт там скрытой, а клавиша её показывает. Spotify, Super+M — показать или спрятать,
Super+Shift+M — перенести туда окно в фокусе:

```kotlin
// Spotify открывается скрытым на особом столе "music" (его app id — "spotify" в Wayland и,
// как класс X11 "Spotify" в нижнем регистре, под XWayland: регистр здесь не важен).
windowRule { appId("spotify"); specialWorkspace = "music" }

keys {
    bind("Super+M", "special-workspace", "music")           // показать "music" и спрятать снова
    bind("Super+Shift+M", "to-special-workspace", "music")  // окно в фокусе — в "music"
    bind("Super+Ctrl+M", "from-special-workspace")          // окно в фокусе — обратно на стену
}
```

Или собственными правилами newm, рядом с остальными в `view { rules { } }`:
`"spotify", "Spotify" -> rule(specialWorkspace = "music")`. В config.json:
`"rules": [ { "app_id_matches": "(?i)^spotify$", "special_workspace": "music" } ]`.
`goToWorkspace = true` в `windowRule` показывает особый стол сразу, как программа открылась.

## colors { }

| Настройка | По умолчанию | Что |

## gestures { }

| Настройка | По умолчанию | Что |
|---|---|---|
| `bind(GestureAction.SWIPE, null, "swipe-3")` | три пальца | перемещение по стене |
| `bind(GestureAction.SWIPE_TO_ZOOM, null, "swipe-4")` | четыре пальца | масштаб |
| `bind(GestureAction.MOVE_RESIZE, "L", "move-1", "swipe-2")` | Logo + тянуть / два пальца | двигать, менять размер |
| `bind(GestureAction.LAUNCHER, null, "swipe-5")` | пять пальцев | лаунчер |
| `lpInertia` | `0.8` | больше — плавнее (и медленнее), 0..1 (анимация `gestureSmoothing`: выключена — вид точно под пальцами) |
| `lpFreq` | `60.0` | как часто опрашивается жест, раз в секунду |
| `enabled` | `true` | жесты тачпада вообще |
| `dbusEnabled` | `true` | жесты, которые присылает другая программа по D-Bus |
| `scalePx` | `800.0` | сколько пикселей движения пальцев — один экран |
| `on("swipe-4", "down") { toggleOverview() }` | | свой жест, см. ниже |

`on(kind, direction, description, modifier) { действие }` выполняет действие, когда пальцы
прошли достаточно в ту сторону: `kind` — `"swipe-3"`, `"swipe-4"` или `"swipe-5"`;
`direction` — `"up"`, `"down"`, `"left"`, `"right"` или `null` (любая сторона); `modifier` —
клавиша, зажатая вместе с ним (`"L"`: Logo); `"move-1"` и `"swipe-2"` без неё не работают (сами
по себе это мышь и прокрутка двумя пальцами). Стороны, которые вы назначили, — ваши; другие
стороны этого жеста делают то, что даёт `bind`: при `on("swipe-4", "down") { toggleOverview() }`
четыре пальца вверх по-прежнему меняют масштаб. `description` показывается в справке по
клавишам (Logo+/).

```kotlin
gestures {
    on("swipe-4", "down", "Все окна") { toggleOverview() }
    on("swipe-3", "up", "Лаунчер", modifier = "L") { enterLauncherOverlay() }
}
```

Справка по клавишам и подсказки во время жеста называют жесты так, как они назначены
(`bind`, `on`, `mouse { }`).

`tuning { swipe { }, swipeZoom { }, move { }, resize { }, moveResize { }, grid { }, interpolation { } }`
хранит тонкую настройку ощущения жестов (`gestureFactor`, `gridM`, `gridOvr`, `lockDist`,
`hyst`, `minDist`, `timeScale`, `sizeAdjustment`), как это было в старом newm.
`grid { debug = true }` пишет в журнал каждый шаг привязки к сетке.

| `exclude` | `[]` | программы, которые никогда не открываются снова, по app id или имени программы: `listOf("steam", "org.telegram.desktop")` |
| `staggerMs` | `300` | программы запускаются по очереди, через столько миллисекунд (0: все сразу) |

## autostart { }

Программы, запускаемые вместе с сессией, по очереди, когда newm уже показан, — один раз за
сессию: сохранённая конфигурация запускает только добавленные записи (а убранные больше не
перезапускает; они продолжают работать). См. [Запуск](startup.md).

| Настройка | По умолчанию | Что |
|---|---|---|
| `stagger` | `400.milliseconds` | время между запусками двух программ (`stagger_ms` в Lua и JSON) |
| `afterReveal` | `true` | запускать, когда newm проявился (false: сразу, пока темно) |
| `desktopEntries` | `false` | ещё и файлы `.desktop` из `~/.config/autostart` и `/etc/xdg/autostart` (учитываются Hidden, OnlyShowIn/NotShowIn с `newm`, TryExec) |
| `afterTimeoutMillis` | `10000` | сколько запись ждёт тех, после которых она запускается (`after`) |
| `app("prog", "arg") { }` | | программа и её аргументы (без оболочки) |
| `script("~/start.sh") { }` | | исполняемый файл |
| `shell("sleep 1; notify-send hi") { }` | | кусок shell |

В фигурных скобках записи: `delay = 2.seconds`, `ifNotRunning = true` (не запускать, если
программа с таким именем уже работает), `restart = OnCrash(maxTimes = 3, within = 1.minutes)`
(или `Always(...)`, `Never`), `after("waybar")`, `env("X", "y")`, `dir = "~"`, `name = "..."`.
В Lua и JSON: `{ "app": ["nm-applet", "--indicator"], "delay_ms": 2000, "if_not_running": true,
"restart": "on_crash", "after": ["waybar"], "env": { "X": "y" }, "dir": "~" }`, либо `"shell"`,
`"script"` (с `"arguments"`) вместо `"app"`.

## env("ИМЯ", "значение")

Переменная окружения для каждой программы, которую newm запускает с этого момента; при запуске
она передаётся и службам сеанса (порталам, программам, которые запускает systemd) — `env` в

## permissions { }

Каким программам можно то, что видит или меняет больше, чем их собственные окна, —
разрешения (permissions) Hyprland. Без правил (по умолчанию) можно всем, как раньше.

| Вызов | Что |
|---|---|
| `rule(program, feature, mode)` | программы, чей путь (`"/usr/bin/grim"`) или имя (`"grim"`) подходит под `program` (регулярное выражение), получают `mode` — `"allow"`, `"ask"` или `"deny"` — для `feature`; решает первое подходящее правило |
| `default(feature, mode)` | что получают программы, о которых нет правила (`enforce_permissions` в Hyprland: `default("screencopy", "ask")`) |

Возможности: `screencopy` (снимки и запись экрана или окна: grim, wf-recorder, портал
показа экрана), `window-list` (доки и панели задач), `clipboard` (менеджеры буфера обмена,
читающие чужие копирования), `panels` (панели, обои, лаунчеры, программы уведомлений), `lock`
(блокировщики экрана), `monitors` (расстановка и выключение мониторов: kanshi, wlr-randr),
`gamma` (ночной свет: wlsunset, gammastep).

`"ask"` — для `screencopy`: снимки программы ждут, пока карточка спрашивает — *Разрешить*
(пока программа работает), *Разрешить до выхода из newm*, *Запретить* (закрыть карточку —
значит нет). Остальные возможности решаются при подключении программы, поэтому для них
`"allow"` или `"deny"`. Правила действуют для программ, подключившихся после изменения. Lua и
JSON: `permissions = { rules = { { program = "/usr/bin/grim", feature = "screencopy", mode = "allow" } }, defaults = { screencopy = "ask" } }`.

## misc { }

Настройки `misc` из Hyprland, которые есть в newm.

| Настройка | По умолчанию | Что |
|---|---|---|
| `swallow` | `false` | «проглатывание» окон: окно, запущенное из терминала (видеоплеер, просмотрщик картинок), занимает место терминала, а терминал возвращается, когда окно закрывается (`enable_swallow` в Hyprland; действие клавиши `swallow` делает обратное для одного окна) |
| `swallowApps` | распространённые терминалы (foot, alacritty, kitty, wezterm, ghostty, konsole, GNOME, xterm, ...) | терминалы, которые проглатывают: регулярное выражение для их app id (`swallow_regex`) |
| `swallowExceptTitles` | `""` | терминал с подходящим под это заголовком не проглатывает (`swallow_exception_regex`): `"wev|vim"` |
| `focusOnActivate` | `true` | окно, просящее фокус по уважительной причине (ссылка, открытая в браузере), получает его; `false`: только отмечается (`focus_on_activate`) |
| `wakeOnInput` | `true` | клавиша, щелчок или движение мыши снова включают погасшие экраны (`key_press_enables_dpms`, `mouse_move_enables_dpms`) |
| `vrr` | `false` | переменная частота обновления (FreeSync, Adaptive-Sync) на каждом мониторе, где она есть (`vrr`) |
| `middleClickPaste` | `true` | выделенное вставляется средней кнопкой (`middle_click_paste`); со следующего запуска |
| `backgroundColor` | тёмно-серый | цвет под всем, где нет обоев (`background_color`) |

## windowRule { }, layerRule { }

Правила Caulis — для того, чего нет в `view { rules }` newm (правила окон Hyprland о том, как
окно себя ведёт). Куда окна попадают, решает newm: `view { rules }`.

```kotlin
windowRule { appId("mpv"); keepAwake = true }                         // idle_inhibit
windowRule { appId(Regex(".*")); ignore(WindowRequest.MAXIMIZE) }   // suppress_event maximize
windowRule { title("Firefox — Sharing Indicator"); hiddenFromCapture = true }   // no_screen_share
windowRule { appId("steam"); takesFocus = false }                     // no_initial_focus
windowRule { appId("org.gnome.Calculator"); minSize(300, 400) }       // min_size
layerRule { namespace("fuzzel"); blur = true; dimAround = 0.4f }     // layerrule blur, dim_around
```

Какие окна: `appId(...)`, `title(...)` (текст или `Regex`), `program(...)`, `initialAppId`,
`initialTitle`, `isXwayland()`, `isFloating()`, `isFullscreen()`, `unless { }`, `anyOf { }`,
`where { window -> ... }`. Что делают: `keepAwake`, `ignore(WindowRequest.FULLSCREEN, MAXIMIZE,
MINIMIZE, ACTIVATE, RESTORE)`, `hiddenFromCapture`, `takesFocus`, `minSize`, `maxSize`,
`tags(...)`. Панели: `namespace(...)`, `layer(...)`; `blur`, `cornerRadius`, `shadow`,
`opacity`, `dimAround`, `hiddenFromCapture`. Пока только в config.kts.

## Всё, что может клавиша

Внутри `keys { }`:

| Вызов | Что делает |
|---|---|
| `launch("команда")` | запустить программу |
| `move(di, dj)` | фокус на соседнее окно (`-1, 0` слева, `0, 1` ниже) |
| `moveFocusedView(di, dj)` | переместить окно в фокусе на плитки |
| `resizeFocusedView(di, dj)` | сделать его шире или выше на плитки (отрицательные: меньше) |
| `basicScale(ds)` | масштаб: `1` отдалить, `-1` приблизить |
| `basicMove(di, dj)` | сдвинуть вид по стене |
| `fitFocusedView()` | масштаб, при котором окно заполняет экран |
| `sideBySide()` | окно и его сосед рядом, и обратно |
| `toggleOverview(onlyActiveWorkspace = false)` | обзор |
| `toggleFullscreen()` | полный экран и обратно |
| `toggleFocusedViewFloating()` | плавающее окно и обратно |
| `moveInStack(1)` | следующее окно стопки |
| `cycleViews(1)`, `cycleViews(-1)`, `gotoView(index)` | окна по очереди или по номеру |
| `moveWorkspace(1)`, `changeFocusedViewWorkspace(1)` | стена следующего монитора; отправить окно туда |
| `swallowFocusedView()` | окно занимает место того, из которого его запустили |
| `closeFocusedView()` | закрыть окно |
| `enterLauncherOverlay()` | лаунчер |
| `toggleKeyHelp()` | подсказка по клавишам |
| `toggleClipboard()` | история буфера обмена |
| `screenshot()`, `screenshotScreen()`, `screenshotWindow()` | выбор снимка; экран; окно |
| `restoreRest()` | окна, оставленные при возвращении сессии (больше `session { maxWindows }`) |
| `scratchpad("имя")` | показать или спрятать scratchpad |
| `ensureLocked(dim = true)` | заблокировать |
| `updateConfig()` | перечитать конфигурацию |
| `terminate()` | выйти из сеанса |
| `command("имя", "аргумент")` | одна из команд `newm cmd`: `command("bar", "power")` |
| `caulis.run("volume +5")` | действие Caulis: `"volume -5"`, `"volume mute"`, `"mic-mute"`, `"brightness +5"`, `"keyboard-layout next"` |

В Lua и JSON действие — это текст. `"terminal"` открывает найденный newm терминал. Иначе это
имя вызова в snake_case и его аргументы: `"move -1 0"`,
`"toggle_overview only_active_workspace=true"`, `"launch firefox"`, `"screenshot"`,
`"toggle_clipboard"`. Действия Caulis пишутся как есть: `"volume +5"`, `"brightness -5"`,
`"mic-mute"`.

## newm cmd

Из терминала, скрипта или панели внутри newm (команда обращается к запущенному newm через
сеансовую шину):

```sh
newm cmd debug                  # раскладка: каждое окно с app id и местом, мониторы
newm cmd config                 # все действующие настройки
newm cmd keys                   # все назначенные клавиши, как "Super+Shift+H  Сдвинуть окно влево"
newm cmd update-config          # перечитать конфигурацию
newm cmd lock                   # заблокировать экран
newm cmd open-launcher          # лаунчер (close-launcher закрывает)
newm cmd launcher firefox       # запустить программу, как это делает лаунчер
newm cmd inhibit-idle           # ни блокировки, ни сна, пока работает (Ctrl+C завершает)
newm cmd caffeine [30|on|off]   # экран не гаснет: на минуты, пока не выключите, или выключить
newm cmd clean                  # прибрать стену
newm cmd bar power              # окошко панели: calendar, volume, network, bluetooth,
                                #   battery, power, quick, colors, tray 0, close
newm cmd colors [nord|wallpaper|#5b8cc8]   # текущие цвета или новые
newm cmd displays extend        # второй монитор: extend, mirror, laptop, other
newm cmd scratchpad drop        # показать или спрятать scratchpad
newm cmd special music          # показать или спрятать особый рабочий стол ("special" без имени)
newm cmd restart                # завершить newm, чтобы он запустился снова (не под блокировкой)
newm cmd restart keep           # то же, и ваши окна откроются снова
newm cmd restore-rest           # окна, оставленные тогда (больше session { maxWindows })
newm cmd autostart              # программы из autostart { } и как каждая из них
newm cmd play-startup-sound     # звук запуска сейчас (или пресет: play-startup-sound glass)
newm cmd log                    # области журнала
newm cmd log input 3            # одна область журнала подробно (0..3), сразу; "log input reset": обратно
newm cmd full-redraw on         # каждый кадр целиком (для мерцания); off: обратно
newm cmd unlock                 # снять блокировку без пароля: выключено, пока нет enableUnlockCommand = true
```

`newm cmd unlock` по умолчанию выключена: иначе любая запущенная вами программа могла бы
снять блокировку без пароля. Включайте её (`enableUnlockCommand = true`,
`enable_unlock_command` в Lua и JSON) только на компьютере для тестов; иначе она отвечает
«Disabled».

Другие команды `newm`: `newm help`, `newm --version`, `newm install-session`.
