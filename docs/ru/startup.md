# Запуск

[English](../en/startup.md) · **Русский**

Когда newm запускается, экран остаётся чёрным — без текстовой консоли и недорисованной
панели, — пока newm не готов: первые кадры нарисованы, панели нарисованы один раз. Потом newm
плавно проявляется под мягкий звук, и только тогда по очереди запускаются программы сессии,
чтобы запуск не дёргался. Всё это — в `config.kts` (см. [Все настройки](settings.md)):

```kotlin
autostart {
    app("waybar")
    app("nm-applet", "--indicator") {
        delay = 2.seconds                                     // подождать ещё столько
        ifNotRunning = true                                   // не запускать, если уже работает
        restart = OnCrash(maxTimes = 3, within = 1.minutes)   // перезапускать после падения
    }
    shell("sleep 1; notify-send 'Привет'")
    desktopEntries = true    // и программы из ~/.config/autostart (как в других окружениях)
}
reveal { fadeMillis = 600 }                       // enabled = false: без чёрного старта
startupSound { preset = "classic"; volume = 0.6 }  // enabled = false: тихо
```

- **Один раз за сессию.** Сохранённая конфигурация не запускает программы заново: запускаются
  только добавленные записи, а убранные больше не перезапускаются (они продолжают работать).
  `newm cmd autostart` показывает их и как каждая из них.
- **Порядок.** По очереди, через `stagger` (400 мс); `after("waybar")` ждёт, пока waybar
  запустится. Окна `newm cmd restart keep` (а с `session { restoreAtLogin = true }` — окна
  прошлой сессии) открываются после них, так же по очереди.
- **Звуки** синтезирует сам newm — `"airy"`, `"classic"`, `"glass"`, `"soft"` — и хранит в
  `~/.cache/newm/sounds`; `file = "~/sounds/hello.ogg"` играет ваш файл. `newm cmd
  play-startup-sound glass` проигрывает пресет сейчас. Играют их pw-play, paplay или aplay
  (или ваш `player`).

## Быстрее запуск

Скрипт запуска newm хранит кеш загруженных классов Java (JDK AOT-кеш, в `~/.cache/newm/aot/`),
свой для каждой сборки newm: первый запуск после обновления создаёт его (когда newm
завершается: выход из сессии один раз займёт на 5–20 секунд дольше), а все следующие запуски
быстрее — на ноутбуке автора первый кадр примерно через 0,9 с вместо 2,1 с. Неподходящий
кеш отмечается только в его журнале и создаётся заново. Запуску newm кеш никогда не мешает:
если папку кеша нельзя записать (её создал root, диск только для чтения) или в её пути есть
`:` или `,`, newm запускается без кеша, а если Java не запускается с кешем — ещё раз без него.
`NEWM_AOT=0` выключает его. Сборки различаются по Java, по месту, где лежит newm (путь в
Nix store свой у каждой сборки, хотя время у всех файлов там одно), по размерам и времени
jar-файлов и по опциям Java (`JAVA_OPTS`, `NEWM_OPTS`).

Скрипт запуска остаётся, пока newm работает (как его родитель: `newm cmd restart` завершает
newm с кодом 3, и скрипт запускает его снова). Что посылают скрипту — `pkill newm`, конец
сеанса, — он передаёт newm и завершается вместе с ним. Под `dev/newm-dev` (он сам
перезапускает newm, `NEWM_SUPERVISED=1`) newm занимает место скрипта: там его завершает
`pkill -f newm.MainKt`.
