# Если что-то пошло не так

[English](../en/troubleshooting.md) · **Русский**

## Сначала: где newm говорит, что не так

- **Журнал**: `~/.local/state/newm/newm.log`. Журнал предыдущего запуска — в `newm.log.old`
  (каждый запуск переносит прошлый журнал туда), так что после падения смотрите `newm.log.old`.
- **Подробнее**: обычно в журнале только проблемы. Чтобы одна область писала подробно, пока
  newm работает: `newm cmd log input 3` (`newm cmd log` перечисляет области;
  `newm cmd log input reset` возвращает как было). Всё с самого запуска: `CAULIS_LOG=2 newm`
  (или `3`: очень много). Собственные части newm пишут под своими именами, их тоже можно
  поднять при запуске: `CAULIS_LOG="1,bar=3,sound=3,network=3,bluetooth=3" newm`.
- **Запустите из текстовой консоли** (Ctrl+Alt+F3, войдите, наберите `newm`), если с экрана
  входа он не запускается: то, что newm говорит до открытия журнала, будет видно прямо там.
- **Как выйти**: Logo+Shift+Escape завершает сеанс. Из другой консоли (Ctrl+Alt+F3, войдите)
  newm завершает `pkill newm` (скрипт запуска передаёт сигнал newm). Всё ещё работает (зависла
  сама Java): `pkill -KILL -f newm.MainKt`.

Журнал с уровнем 3 у области `input` записывает нажатые клавиши (но никогда — пока экран
заблокирован). Не отправляйте такой журнал, если вы в это время вводили пароль.

## newm не запускается или экран остаётся чёрным

Если запустить newm из текстовой консоли, он скажет, чего не хватает, прежде чем сдаться:

| Он пишет | Что делать |
|---|---|
| `Missing system libraries: ...` | установите их (см. [Установка](install.md#что-нужно)) |
| `No GPU was found (/dev/dri is missing)` | установите драйвер видеокарты: Mesa для AMD и Intel, NVIDIA 545 или новее. В NixOS: `hardware.graphics.enable = true;` |
| `libseat is missing` | установите seatd / libseat (работает и с systemd-logind) |
| `XDG_RUNTIME_DIR is not set` | войдите обычным образом (экран входа или текстовая консоль), а не через `su` или `sudo` |
| `Running as root` | запускайте от обычного пользователя |
| `Could not open the seat` | запускайте из текстовой консоли вошедшего пользователя |
| `newm needs Java 26 or newer` | установите Java 27 (в Arch: `sudo pacman -S jdk-openjdk`) или укажите её в `JAVA_HOME` |
| `The GPU driver lacks ...` | драйвер видеокарты слишком старый или его нет |

Ещё случаи:

- **На NVIDIA**: драйверу нужен kernel modesetting (`nvidia-drm.modeset=1`; в NixOS
  `hardware.nvidia.modesetting.enable = true;`).
- **В виртуальной машине**: newm нужна виртуальная видеокарта с 3D (QEMU / virt-manager:
  virtio с включённым 3D-ускорением). Без неё рисовать нечем.
- **Всё медленно, указатель отстаёт**: поищите в журнале `Drawing on the processor`. Драйвер
  видеокарты не запустился, и newm рисует без него. Проверьте драйвер, как выше.
- **Сразу возвращает на экран входа**: запустите newm из текстовой консоли, чтобы увидеть
  причину, затем посмотрите `newm.log.old`.
- **Чёрный экран с указателем**: подождите несколько секунд (первый запуск компилирует
  конфигурацию). Всё ещё чёрный? Ctrl+Alt+F3, войдите, посмотрите журнал, `pkill newm`.

## Конфигурация

- **Карточка в правом верхнем углу сообщает об ошибке в конфигурации.** В ней указаны файл
  и строка. Исправьте строку и сохраните — карточка исчезнет. До тех пор newm работает с
  прежними, рабочими настройками. Запутались? Переименуйте `~/.config/newm` и запустите снова:
  newm запишет новую.
- **Нет клавиш или панели с `config.json` или `config.lua`** (например, из
  `programs.newm.settings` в NixOS или из home-manager): такой файл — это вся конфигурация. Без
  `keys` клавиш нет; без `top_bar = { enabled = true }` нет панели. Начните с
  `~/.config/newm/examples/` или используйте `config.kts`. Чтобы выйти пока что: Ctrl+Alt+F3,
  `pkill newm`.
- **Изменение `programs.newm.settings` (NixOS) ничего не меняет**: оно доходит только до
  пользователей, у которых ещё нет `~/.config/newm`. Удалите (или переименуйте) свою папку,
  чтобы снова начать с системной.
- **Клавиша ничего не делает**: `keys { }` — это весь ваш список. Есть ли в нём эта клавиша?
  Logo+/ показывает клавиши, у которых есть описание. В работающем newm `newm cmd log input 3`
  записывает в журнал каждое нажатие.

## Клавиатура

- **Не та раскладка или нет второй**: без `keyboard { layouts }` newm берёт раскладки
  системы из `/etc/X11/xorg.conf.d` (их пишет `localectl set-x11-keymap`), а если их нет —
  раскладку вашего языка рядом с английской. `services.xserver.xkb` из NixOS не читается.
  Задайте сами:

  ```kotlin
  keyboard { layouts = "us,ru"; options = "grp:alt_shift_toggle" }
  ```

  Тогда переключает Alt+Shift; остров раскладки на панели тоже.
- **Сочетания с Logo не работают во вложенном newm** (newm в окне внутри другого рабочего
  стола): внешний рабочий стол перехватывает Logo первым. Попробуйте из текстовой консоли.

## Экран блокировки

- **Пароль не принимается**: newm проверяет его через службу PAM `login`
  (`/etc/pam.d/login`). Есть ли этот файл? Если `login` сначала просит отпечаток пальца
  (fprintd), приложите палец или уберите отпечатки из цепочки `login`. Если запустить
  `CAULIS_LOG="1,auth=2" newm`, журнал пишет «PAM Backend: not successful» на каждый
  отвергнутый пароль.
- **Заблокировано, и не войти**: переключитесь в другую консоль (Ctrl+Alt+F3), войдите,
  `pkill newm`. Открытые программы завершатся вместе с ним.
- **Своя программа блокировки** (swaylock, ...): `panels { lock { program = "swaylock -f" } }`.
- **Блокирует или засыпает слишком рано**: `energy { idleTimes = listOf(120, 300, 600) }` — в
  секундах: «простой», блокировка, сон. `listOf(600, 1200)` блокирует через 20 минут и никогда
  не усыпляет. Кофеин в быстрых настройках откладывает всё это на время.

## Панель и её окошки

Каждое окошко узнаёт о компьютере через обычную службу. Если её нет, окошко пустое или
ничего не делает (остальное работает):

- **Окошко Wi-Fi пишет «NetworkManager is not running»**: newm использует NetworkManager.
  Запустите его (`systemctl enable --now NetworkManager`; NixOS:
  `networking.networkmanager.enable = true;`). Только с iwd или systemd-networkd окошко сети
  показать не может.
- **Нет острова Bluetooth**: нет адаптера Bluetooth или не запущен BlueZ
  (`systemctl enable --now bluetooth`; NixOS: `hardware.bluetooth.enable = true;`).
- **Окошко громкости пустое, «No sound device»**: оно использует `pactl`. Установите его
  (Arch: `libpulse`, Debian: `pulseaudio-utils`, NixOS: `pkgs.pulseaudio`) и запустите
  PipeWire с pulse-частью или PulseAudio.
- **Клавиши громкости ничего не делают**: они используют `wpctl` (WirePlumber).
- **Яркость не меняется**: установите `brightnessctl`. Ползунок яркости виден, только если в
  `/sys/class/backlight` есть экран.
- **Нет режимов питания**: не запущен power-profiles-daemon.
- **Нет значка в трее**: nm-applet и blueman скрыты нарочно (`trayHide`). Для остальных нужно,
  чтобы программа поддерживала трей (StatusNotifierItem); некоторые показывают значок, только
  если их запустить с особым флагом.
- **Уведомления программ не видны**: newm показывает только свои сообщения. Запустите
  программу уведомлений: `onStartup { launch("mako") }`.

## Программы

- **Программа не открывается или сразу закрывается**: возможно, это программа X11. Установлен
  ли Xwayland (`xorg-xwayland` в Arch, `xwayland` в Debian; модуль NixOS включает его сам)?
  Запустите программу из терминала внутри newm и посмотрите, что она пишет.
- **Программа X11 выглядит мелкой**: newm не растягивает программы X11, поэтому они чёткие. Он
  сообщает им настоящий DPI экрана; программа, которая его не учитывает, остаётся мелкой.
  Большинство программ может работать как Wayland-программы: newm уже просит об этом
  программы GTK, Qt, Firefox и Electron, которые запущены из него. Для запущенной
  иначе попробуйте `--ozone-platform=wayland` (Electron, Chromium) или
  `QT_QPA_PLATFORM=wayland`.
- **Программа выглядит размытой**: это программа X11 на экране с дробным масштабом (1.25)?
  Запустите её как Wayland-программу (см. выше).
- **Окно больше своей плитки или сжато**: некоторые программы нельзя сделать маленькими
  (Spotify: 800 × 600). newm рисует их в форме плитки и уменьшает; это
  `view { minSizeKeepsShape, minSizeShrink }`.
- **Не работает демонстрация экрана или окно выбора файлов**: установите `xdg-desktop-portal`,
  `xdg-desktop-portal-gtk` и `xdg-desktop-portal-wlr` и скажите порталу использовать wlr для
  демонстрации экрана (см. [Установка](install.md#сборка-и-установка), а для NixOS —
  [здесь](install.md#что-стоит-добавить)). newm сам передаёт порталам своё окружение.
- **Игра или видео на весь экран дёргается или рвётся**: напишите об этом в issue с
  `newm cmd debug` и журналом; попробуйте `newm cmd full-redraw on` и посмотрите, меняется ли
  что-то.

## Экран

- **Окна мерцают или части не перерисовываются**: `newm cmd full-redraw on` рисует каждый кадр
  целиком. Если с ним мерцание пропало, напишите об этом в issue. `off` возвращает как было.
- **В терминале крошечный текст**: размер шрифта определяет сам терминал. Для foot задайте
  его в `~/.config/foot/foot.ini` (`font=monospace:size=11`). На экране с высокой чёткостью
  `output("eDP-1") { scale = 1.25 }` сделает всё крупнее.
- **Программа-панель перекрывает окна**: скорее всего, она не резервирует под себя место
  (exclusive zone). В waybar за это отвечает `"exclusive": true` — это его значение по
  умолчанию.
- **Второй монитор ничего не показывает или показывает то же самое**: клавиша дисплея (F7 на
  многих ноутбуках) или `newm cmd displays extend` (или `mirror`, `laptop`, `other`).

## Тачпад

- **Касание не щёлкает**: `input { tapToClick = true }`.
- **Прокрутка идёт не в ту сторону**: `input { naturalScroll = true }` (или `false`).
- **Три или четыре пальца ничего не делают**: знает ли libinput этот тачпад? Выполните
  `newm cmd log gestures 3`, проведите пальцами и посмотрите журнал.

## newm нет на экране входа

Выполните `newm install-session` (спросит пароль). В NixOS его добавляет модуль; нужен
включённый экран входа, или запускайте newm из текстовой консоли.
